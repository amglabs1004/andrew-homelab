## Step 1: SSH on the ISR

I set up SSH first so I could work on the router from my PC instead of the console cable.

```
hostname ISR-LAB
ip domain-name homelab.local
username admin privilege 15 secret <password>
enable secret <password>
crypto key generate rsa modulus 2048
ip ssh version 2
ip ssh time-out 60
ip ssh authentication-retries 3

line vty 0 4
 transport input ssh
 login local
 exec-timeout 15 0
 logging synchronous

service password-encryption
```

* `hostname` and `ip domain-name` have to be set before generating the RSA key.
* `transport input ssh` disables Telnet.
* I SSH to G0/0/0 because it's on the same subnet as my PC, so no routing is needed for management.

**Verify:** `show ip ssh` should show "SSH Enabled - version 2.0".

## Step 3: Router-on-a-stick for VLAN 40

**Design choice:** I made the ISR ↔ switch link an 802.1Q trunk with **native VLAN 99**. Management traffic stays untagged, so 10.10.99.1 can stay on the physical G0/0/1 and my existing access keeps working. VLAN 40 is tagged and goes to a subinterface.

### ISR
```
interface g0/0/1
 description TRUNK-TO-SW1-Gi0/47
interface g0/0/1.40
 description VLAN40-SERVERS
 encapsulation dot1Q 40
 ip address 10.10.40.1 255.255.255.0
interface g0/0/2
 no description
```

### Switch
```
vlan 40
 name SERVERS

interface gi0/1
 description PROXMOX
 switchport mode access
 switchport access vlan 40
 spanning-tree portfast

interface gi0/47
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 40,99
```

**Verify:** `show mac address-table` showed the ISR's MAC (`4ce1.7516.2651`) on Gi0/47 in **both VLAN 99 and VLAN 40**. Router subinterfaces share the physical interface's MAC, so this confirmed the trunk was carrying tagged VLAN 40 traffic.

## Step 4: Re-IP Proxmox

The web UI was unreachable at the old address, so I made the change at the OptiPlex console (monitor and keyboard, logged in as root).

`/etc/network/interfaces`, vmbr0 block:
```
auto vmbr0
iface vmbr0 inet static
        address 10.10.40.10/24
        gateway 10.10.40.1
        bridge-ports <NIC>
        bridge-stp off
        bridge-fd 0
```

Then I updated `/etc/hosts` from 10.0.0.116 to 10.10.40.10 and applied it:
```
ifreload -a
ping 10.10.40.1
```

**Verify:** `ping 10.10.40.10` from the ISR worked, and Gi0/1 showed connected in VLAN 40.

## Step 5: Reaching the lab from my home network

My PC (192.168.0.x) didn't know the 10.10.x.x networks were behind the ISR.

* **Temporary:** a persistent route on my PC: `route -p add 10.10.0.0 mask 255.255.0.0 <ISR G0/0/0 IP>`
* **Permanent:** a static route on the TP-Link router so every home device can reach the lab:

| Field | Value |
|-------|-------|
| Network Destination | 10.10.0.0 |
| Subnet Mask | 255.255.0.0 |
| Gateway | 192.168.0.191 (ISR G0/0/0) |
| Interface | LAN |

A single /16 covers every lab VLAN (10, 20, 30, 40, 99), so new VLANs don't need new routes.

### Problem: SSH and routes suddenly stopped working
The ISR's DHCP lease moved from 192.168.0.190 to **192.168.0.191**, and another device on the network took .190. I found the ISR in the TP-Link DHCP client list by MAC (`4C-E1-75-16-26-50`).

**Fix:** a DHCP reservation for the ISR at 192.168.0.191, with the static routes pointed there.

**Result:** Proxmox web UI loads at `https://10.10.40.10:8006`.

### Problem: Jellyfin crashed after adding a show
```
Active: failed (Result: signal)
Process: ... (code=killed, signal=ABRT)
jellyfin.service: Start request repeated too quickly.
```
* `ip -br a` showed the network was fine (10.10.40.20), so it was the service itself.
* **Cause:** the container's root disk was full of media.
* **Fix:** resized the root disk in Proxmox, then:
  ```
  systemctl reset-failed jellyfin
  systemctl start jellyfin
  ```
* **Follow-up:** move media to the Proxmox host and pass it in with a mount point (`mp0: /mnt/media,mp=/media`).

### Problem: Wrong folder structure
I accidentally created `The Chair Company/Season 1/Season 1/`. Fixed it with:
```
cd "/mnt/media/shows/The Chair Company/Season 1"
mv "Season 1"/* .
rmdir "Season 1"
```
`rmdir` only removes empty folders, so it can't delete media by accident.

## Step 7: NAT so the lab can reach the internet

**Symptom:** no posters or metadata in Jellyfin, and Identify searches returned nothing.

**Cause:** traffic from 10.10.x.x could leave through the home router, but replies had no way back, because the TP-Link only NATs its own 192.168.0.x subnet.

```
ip access-list extended NAT-LAB
 deny   ip 10.10.0.0 0.0.255.255 192.168.0.0 0.0.0.255
 permit ip 10.10.0.0 0.0.255.255 any

interface g0/0/0
 ip nat outside
interface g0/0/1
 ip nat inside
interface g0/0/1.40
 ip nat inside

ip nat inside source list NAT-LAB interface g0/0/0 overload
```

How it works:
* In a NAT ACL, `permit` means **translate**, not "allow."
* The **deny** line exempts lab-to-home traffic. When my PC connects to Proxmox, the replies have to come back from 10.10.40.10, not from the ISR's address, or my PC drops them.
* `overload` = **PAT**. Every lab device shares the ISR's 192.168.0.191 address, with unique source ports tracked in the translation table.
* `interface g0/0/0` uses whatever IP G0/0/0 currently has.
* Each new VLAN subinterface needs its own `ip nat inside`.

**Verify:**
```
show ip nat translations          (ISR)
ping -c 3 1.1.1.1                 (from a lab host: internet)
ping -c 3 api.themoviedb.org      (from a lab host: DNS)
```

The lab is now **double NAT** (ISR, then TP-Link), which is common in homelabs.
